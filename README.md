# BugHunter

Русскоязычный детективный тренажёр по поиску ошибок в Python для школьников 8–11 классов.

## Состояние проекта

Выполнены этапы 1, 2 и 3.1. Созданы адаптивные страницы, восемь миссий, общий редактор и выполнение Python в браузере.

- `/` — главная с примером кода, описанием процесса и превью дел.
- `/missions` — восемь карточек, три категории и фильтр уровня.
- `/missions/[slug]` — история, условие, примеры, мини-теория, подсказки и редактор CodeMirror 6.
- `/profile` — начальный гостевой профиль с нулевыми показателями.
- `/leaderboard` — страница «Рейтинг скоро».
- Неизвестные адреса и slug миссий показывают страницу 404.

Карточки открывают миссии. Во вкладке «Найди строку» можно выбрать строку исходной программы кликом, по номеру или через доступный список. Вкладка «Исправь код» содержит редактируемый черновик. Простой режим даёт альтернативный выбор строки и textarea. Выбранная строка относится к исходной программе и сохраняется независимо от изменений кода. Подтверждение выбора сообщает номер, проверка правильности появится вместе с отправкой решения.

Черновик, выбранная строка и число открытых подсказок сохраняются в `bughunter_draft_v1:<slug>` отдельно для каждой миссии. Восстановление исходного кода требует подтверждения и сохраняет подсказки и выбранную строку. При недоступности localStorage интерфейс сообщает об этом и продолжает работать в памяти. Изменение авторского исходного кода или неподдерживаемая версия записи восстанавливают начальное состояние соответствующей миссии.

«Запустить код» выполняет текущий черновик с аргументами первого публичного примера и показывает возвращённое значение, stdout, stderr и ошибки. `None` отображается как `None (null)`, а ошибка содержит `hasReturnValue: false`. Кнопка отправки отключена с пояснением. Автоматическая проверка правильности предусмотрена на этапе 3.2, XP и игровой прогресс на этапе 4. Пример кода на главной статичен.

## Выполнение Python

Используется зафиксированный Pyodide 314.0.8. Runner из `src/lib/python/runner.ts` создаёт новый module Web Worker для каждого запуска. Worker лениво загружает интерпретатор с `https://cdn.jsdelivr.net/pyodide/v314.0.8/full/`, получает исходник, имя функции, JSON-совместимые аргументы и requestId через сообщения. Постоянная Python-обёртка читает данные из отдельной JSON-переменной, компилирует исходник и вызывает функцию в новом namespace.

Worker собирается из TypeScript отдельной командой esbuild в `public/python.worker.mjs`. `predev` и `prebuild` запускают её автоматически. Это сохраняет настоящий module Worker при сборке Next.js через Turbopack. Сгенерированный файл исключён из Git. После изменения worker-кода во время разработки выполните `npm run build:worker` и обновите страницу.

Лимиты — 30 000 символов кода, 20 000 символов сериализованных аргументов, 16 КБ общего stdout/stderr, 30 000 символов JSON-результата, 30 уровней вложенности и 10 000 значений результата. Допускаются числа, строки, bool, None, списки и словари со строковыми ключами. Не поддерживаются NaN, Infinity, множества, tuple и целые числа вне точного диапазона JavaScript.

Загрузка ограничена 60 секундами. Таймер выполнения на 5 секунд запускается после готовности интерпретатора. По завершении, ошибке, отмене, тайм-ауте или уходе со страницы Worker уничтожается через `terminate()`. requestId и проверка активного запуска защищают от устаревшего ответа. Следующий запуск использует свежий Worker, включая после тайм-аута.

Нужен доступ к CDN. На каждом запуске создаётся свежий интерпретатор, статические файлы могут кешироваться браузером. Web Worker изолирует выполнение от интерфейса, но полноценной защищённой песочницей не является. В MVP поддерживаются простые функции. `input()` отключён, интеграции с файлами пользователя, сетью и дополнительными Python-пакетами отсутствуют. Пользовательский Python исполняется на клиенте. Серверные маршруты исполнения отсутствуют.

## Запуск в Windows PowerShell

Требуется Node.js от 20.9 и npm. В среде разработки проверено с Node.js 26.13.1.

```powershell
cd C:\Users\akimo\work\demo_project
npm.cmd install
npm.cmd run dev
```

Откройте `http://localhost:3000`.

`npm.cmd` работает при блокировке `npm.ps1` политикой выполнения PowerShell. Если ограничений нет, можно использовать обычный `npm`.

## Проверки

```powershell
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run test
npm.cmd run build
```

Для проверки production-сборки после `build` выполните следующую команду.

```powershell
npm.cmd run start
```

Vitest проверяет контракт всех миссий, выбор строки, хранение и повреждённые данные. Авторские тесты запускают фиксированные программы из репозитория локальным Python 3, проверяют все эталонные решения и провал хотя бы одного теста у каждой исходной программы. Бюджет шагов и тайм-аут процесса останавливают бесконечный цикл.

Тесты Runner проверяют раздельные таймеры, отмену, освобождение ресурсов, устаревшие ответы, лимиты вывода, ошибку Worker и повторный запуск. Браузерные тесты запускают настоящий Pyodide на production-сборке через установленный Google Chrome.

```powershell
npm.cmd run build
npm.cmd run test:browser
```

Playwright сам запускает production-сервер на порту 3100 и останавливает его после тестов. Требуются Google Chrome и доступ к CDN. Проверяются числа, списки, False, None, print без перевода строки, stderr, Python-ошибки, лимит вывода, изоляция, тайм-аут, отмена, уход со страницы, отказ сети и ширина 375/1440 px.

Для `npm run test` нужен Python 3 в PATH. Можно указать путь через `$env:BUGHUNTER_PYTHON = 'C:\path\to\python.exe'`. Авторские проверки из `tests/` используются только при разработке. Приложению и Vercel Python не требуется.

## Стек и структура

Next.js App Router, React, TypeScript в строгом режиме, Tailwind CSS 4, ESLint и Lucide. Inter и JetBrains Mono поставляются локально через Fontsource с кириллицей. Рабочие версии зависимостей закреплены в `package.json` и `package-lock.json`.

```text
src/
  app/
    globals.css            дизайн-токены, компоненты и адаптивные стили
    layout.tsx             общий каркас и метаданные
    page.tsx               главная
    missions/page.tsx      каталог
    missions/[slug]/      страница миссии
    profile/              профиль
    leaderboard/          будущий рейтинг
    not-found.tsx          404
    icon.svg               иконка приложения
  components/
    ui.tsx                 логотип, карточки и общие элементы
    site-header.tsx        навигация с активным маршрутом
    site-footer.tsx        подвал
    code-preview.tsx       статичный пример кода
    mission-catalog.tsx    фильтрация каталога
    editor/               переиспользуемый CodeMirror-редактор
    missions/             общий интерфейс исследования миссии
  content/missions.ts      полные данные восьми миссий
  content/mission-tiers.ts общие категории
  lib/line-selection.ts   логика выбора исходной строки
  lib/mission-draft.ts    состояние ученика и localStorage
  lib/python/            протокол, Runner, хук, лимиты и Python-обёртка
  workers/python.worker.ts module Worker с Pyodide
  types/mission.ts         контракт миссии, тестов и трассировки
tests/                    метаданные, состояние и авторские Python-проверки
```

Страницы по умолчанию серверные. Клиентские компоненты отвечают за навигацию, фильтр и исследование миссии. `ReadyMission` содержит весь контракт подготовленного задания, а `LearnerMission` — данные интерфейса. `toLearnerMission` исключает эталон, правильную строку, дополнительные тесты и объяснение из передаваемых клиенту данных. `MissionWorkspace` управляет сценарием, `PythonEditor` отвечает за CodeMirror, `line-selection` за выбор строки, `mission-draft` за состояние. Исполнение Python подключено отдельным слоем. Сравнение с ожидаемым результатом в интерфейсе появится на этапе 3.2.

Чтобы добавить задание, добавьте запись `ReadyMission` в `src/content/missions.ts` с уникальными id и slug и прогоните проверки. Каталог и страницы используют общий набор данных. Для бинарного поиска контракт этого задания задаёт возрастающий список без повторов, чтобы ожидаемый индекс был однозначным.

## Визуальная проверка

- Откройте главную на ширине 375 и 1440 px. Проверьте читаемость, переносы и отсутствие горизонтального скролла страницы.
- Перейдите по кнопке «Начать расследование» и проверьте все фильтры каталога. В полном списке должны быть восемь дел в трёх категориях.
- Откройте все карточки. У каждой свои история, условия, примеры и мини-теория.
- Выберите строку кликом по коду, номеру или через список. Подсветка и сообщение должны соответствовать выбору.
- Перейдите в «Исправь код», измените код, откройте подсказку и обновите страницу. Черновик, гипотеза и подсказка должны восстановиться.
- Откройте другую миссию и вернитесь обратно. Данные миссий должны храниться независимо.
- Проверьте простой режим, восстановление исходного кода, подтверждение и отмену. Подсказки и выбранная исходная строка сохраняются при восстановлении кода.
- Нажмите «Запустить код». В первом деле исходный код возвращает 150 на аргументах `[100, 50, 25]`. Интерфейс сообщает об успешном выполнении функции.
- Вставьте `def sum_prices(prices):` и на следующей строке с четырьмя пробелами `print(prices); return sum(prices)`. При запуске должен появиться результат 175 и stdout со списком.
- Попробуйте `return False`, `return None`, `return 1 / 0` и синтаксическую ошибку. None должен отличаться от отсутствующего результата при ошибке.
- Вставьте бесконечный цикл `while True: pass` внутрь функции. Через 5 секунд после загрузки Python появится тайм-аут. После исправления следующий запуск должен работать.
- Проверьте отмену во время загрузки и выполнения, переход к каталогу при активном запуске и отключённую кнопку отправки.
- Откройте профиль и рейтинг через навигацию. В профиле нулевые показатели, рейтинг помечен «скоро».
- Откройте `/unknown` и `/missions/unknown`. Должна появиться 404 со ссылкой к миссиям.
- Пройдите интерфейс клавишами Tab и Enter. Проверьте видимую рамку фокуса и ссылку перехода к содержимому.
- Включите сокращение движения в системе. Плавная прокрутка и анимации переходов должны отключиться.

## Vercel

Каркас использует стандартную Next.js-сборку и готов для импорта репозитория в Vercel с preset Next.js. Команда сборки `npm run build`. Переменные окружения для этапа 1 не требуются. Публикация предусмотрена на этапе 5.

Python исполняется в браузере внутри отдельного module Web Worker. Проверка решений появится на этапе 3.2. При публикации дополнительно проверьте доступность `/python.worker.mjs` и загрузку Pyodide с CDN.

Требования и порядок разработки находятся в `BugHunter_TZ.md` и `BugHunter_Codex_Prompts.md`.
