# BugHunter

Русскоязычный детективный тренажёр по поиску ошибок в Python для школьников 8–11 классов.

## Состояние проекта

Выполнены этапы 1, 2, 3, 4.1, 4.2A и 4.2B. Созданы адаптивные страницы, восемь миссий, общий редактор, выполнение Python, автоматическая проверка, прогресс, Debug Mode и визуальные награды.

- `/` — главная с примером кода, описанием процесса и превью дел.
- `/missions` — восемь карточек, три категории и фильтр уровня.
- `/missions/[slug]` — история, условие, примеры, мини-теория, подсказки и редактор CodeMirror 6.
- `/profile` — гостевой профиль с реальными XP, звёздами, достижениями и прогрессом по уровням.
- `/leaderboard` — страница «Рейтинг скоро».
- Неизвестные адреса и slug миссий показывают страницу 404.

Карточки открывают миссии. Во вкладке «Найди строку» можно выбрать строку исходной программы кликом, по номеру или через доступный список. Вкладка «Исправь код» содержит редактируемый черновик. Простой режим даёт альтернативный выбор строки и textarea. Выбранная строка относится к исходной программе и сохраняется независимо от изменений кода. Её правильность проверяется при отправке решения.

Черновик и выбранная строка сохраняются в `bughunter_draft_v1:<slug>` отдельно для каждой миссии. Существующие записи сохраняют формат. Подсказки из старого черновика импортируются при первом открытии, дальнейшие подсказки учитываются в модуле прогресса. Восстановление исходного кода требует подтверждения и сохраняет подсказки, попытки и выбранную строку. При недоступности localStorage интерфейс сообщает об этом и продолжает работать в памяти. Изменение авторского исходного кода или неподдерживаемая версия черновика восстанавливают начальное состояние соответствующей миссии.

«Запустить код» проверяет текущий черновик на всех публичных примерах и показывает вход, ожидаемый и фактический результат, stdout, stderr и ошибки каждого теста. «Отправить решение» проверяет публичные и дополнительные тесты, а также выбранную исходную строку. Решение принимается только при успешном полном наборе и правильном выборе строки. После принятия показывается объяснение бага.

Сравнение структурное — учитывает типы, порядок списков, точные строки, вложенные объекты и None/null. False отличается от 0, True от 1. Эталонный текст кода в проверке не участвует. Для дополнительных тестов интерфейс показывает статус и тип ошибки, сохраняя входные данные и вывод внутри проверяющего слоя.

`submitAttempts` хранится в черновике миссии и увеличивается при старте каждой отправки, включая отменённую или прерванную ошибкой. Обычный запуск не меняет счётчик. Старые записи без этого поля читаются с нулевым счётчиком и сохраняют код, строку и подсказки. Восстановление кода сохраняет число отправок. Принятие решения относится к проверенному снимку кода и строки. Последующие изменения помечают результат устаревшим, сохраняя заработанный прогресс.

## Прогресс и награды — этап 4.1

Награда выдаётся только после принятой отправки: все публичные и дополнительные тесты пройдены, выбрана правильная исходная строка. Обычный запуск и ошибочные решения XP не дают.

| Условия прохождения                                               | Звёзды | XP  |
| ----------------------------------------------------------------- | ------ | --- |
| Без подсказок, не более 2 учитываемых отправок                    | 3      | 100 |
| Не более 1 подсказки и 4 отправок, если не выполнено условие выше | 2      | 75  |
| Остальные принятые решения                                        | 1      | 50  |

Для каждой миссии сохраняется лучший результат. Общий XP — сумма лучших XP по миссиям. Повторная отправка не увеличивает XP, улучшение с 50 до 100 добавляет только 50. Подсказки, открытые во время проверки, учитываются. Отмена, ошибка Worker, сбой и тайм-аут загрузки не расходуют попытки награды. Ошибка программы, неверная строка и тайм-аут исполнения расходуют попытку.

Попытки награды учитываются отдельно от прежнего `submitAttempts`. История исходов до этапа 4.1 неизвестна, поэтому прежний общий счётчик сохранён, а новый начинается с нуля. После успешного прохождения доступна подтверждаемая кнопка «Пройти заново»: она начинает новую сессию с нулевыми подсказками и попытками. Код, выбранная строка, общий счётчик отправок и лучший результат сохраняются. Незавершённую сессию так сбросить нельзя.

Все миссии «Новичка» открыты сразу. «Практик» открывается после всех трёх миссий «Новичка», «Детектив» — после всех трёх миссий «Практика». Ограничение проверяется на карточках, при открытии URL и перед записью результата. Без прогресса закрытая миссия не монтирует редактор.

Достижения открываются один раз: первая завершённая миссия, 3 звезды, прохождение без подсказок, 3 завершённые миссии, все 8 миссий. Профиль показывает их состояние и лучшие результаты.

Типы и правила находятся в `src/lib/progress/`. `LocalProgressRepository` реализует отдельный интерфейс репозитория для будущей синхронизации. Формат имеет `version: 1`. Ключ `bughunter_progress_v1` содержит снимок прогресса, ключи `bughunter_progress_v1:event:<id>` — журнал неизменяемых событий. Журнал восстанавливает снимок и объединяет результаты вкладок без потери отдельных записей. Подписка на `storage` обновляет интерфейс других вкладок.

Повреждённые записи пропускаются с уведомлением. Неподдерживаемая версия сохраняется без перезаписи, новая работа продолжается в памяти. При запрете хранилища или переполнении сохраняется состояние в памяти с предупреждением. Следующая запись повторяет сохранение. Очистка прогресса требует подтверждения и удаляет только его ключи, оставляя черновики. Данные локальные и могут быть изменены владельцем браузера. Авторизация, Supabase, Debug Mode и новые анимации не добавлены.

## Визуальные награды — этап 4.2B

После принятой актуальной отправки появляется «Дело раскрыто!»: название миссии, звёзды, фактическая дельта XP, объяснение ошибки и навигация. Первый результат показывает начисленный XP, улучшение — только разницу, повтор без улучшения — «Лучший результат сохранён» и 0 новых XP. Счётчик общего опыта и полоса обучения обновляются плавно.

`src/lib/reward-effects.ts` — отдельный слой представления. Он вызывается из обработчика завершения проверки **после** существующего `recordOutcome` и читает готовый `AwardReceipt`. Он не начисляет XP, не пишет localStorage и не меняет правила прогресса. Проверяются совпадение миссии, кода и выбранной строки. Идентификатор отправки принимается один раз в рамках провайдера, включая устаревшие результаты. Загрузка сохранённых данных не вызывает визуальное событие. При изменении кода, строки, новой проверке или переходе на другую миссию панель и уведомления прежней отправки снимаются.

Переиспользуемые компоненты: `MissionSuccess`, `StarReveal`, `XpReward`, `AchievementNotification`, `LevelUnlockedNotification`, `RewardNotifications`, `ProgressMeter`. Новые достижения показываются компактной группой. Уровни определяются сравнением доступности до и после подтверждения через существующие правила. Ссылка ведёт к категории, её новые карточки выделяются на 20 секунд без записи в хранилище.

Эффекты конечные: появление панели, последовательные звёзды, мягкое свечение и 14 небольших частиц внутри панели; всё завершается за 1,8 секунды. Числовой счётчик использует короткий `requestAnimationFrame`, прочие эффекты — CSS. Уведомления закрываются через 9 секунд с коротким исчезновением. Фокус или наведение приостанавливают закрытие; есть клавиатурная кнопка закрытия с переводом фокуса к следующей миссии. Таймеры, кадры и обработчики очищаются при размонтировании. Никакие части редактора Python не анимируются.

`prefers-reduced-motion` отключает частицы, перемещения и анимацию счётчика, сохраняя все сведения о награде. Включение Reduce Motion во время эффекта прекращает его; обратное переключение не возобновляет старую награду. Карточки, кнопки, подсказки и результаты тестов имеют короткие микропереходы. Новые анимационные зависимости не добавлены.

Проверки: `tests/reward-effects.test.ts`, расширенный `tests/browser/progress.spec.ts` и `tests/browser/reward-effects.spec.ts`. Браузерные отправки используют настоящий Pyodide. Дополнительно проверяются неизменность прогресса после визуальных эффектов, устаревшая успешная отправка, Reduce Motion, перезагрузка, навигация и ширина 375 px.

## Выполнение Python

### Пошаговая отладка — этап 4.2A

Кнопка «Отладка» записывает реальное выполнение текущего черновика на первом публичном примере миссии. Скрытые тесты, автоматическая проверка и состояние прогресса в этом сценарии не используются. Это запись с последующим просмотром, без паузы Python, breakpoints и продолжения живого процесса. Run и Submit используют свои прежние Worker и могут работать независимо от отладки.

`src/lib/trace/` содержит типы `TraceStep[]`, константы, Python-драйвер, `TraceRunner`, управление просмотром и React-хук. `TraceRunner` переиспользует таймеры, идентификаторы и завершение Worker существующего `PythonRunner`. Worker выбирает отдельный драйвер по `mode: "trace"`. Драйвер компилирует код с именем `<bughunter-user>` и через `sys.settrace()` записывает только кадры этого файла: `call`, `line`, `return`, `exception`, локальные переменные, номер строки, функцию и глубину стека. Внутренний код, стандартная библиотека и служебный драйвер в запись не входят.

Событие `line` происходит **до исполнения строки**. Снимок показывает состояние в этот момент. На `return` выражение уже вычислено. Выход из-за исключения отличают от настоящего возврата `None`. Семантика событий описана в [документации Python](https://docs.python.org/3/library/sys.html#sys.settrace).

Снимки отправляются из Python в Worker JSON-строками, затем сообщениями в Runner. PyProxy в React не передаются. Представление поддерживает int, float, bool, str, None, list, tuple и dict. Встроенные типы проверяются точно, неизвестные объекты представлены именем типа без вызова пользовательского `__repr__` или `__str__`. Циклы ссылок, глубина, число элементов и длина текста ограничены. Значения снимков не меняются после последующего изменения Python-объекта.

Лимиты: 300 шагов, 512 КиБ JSON-трассы, 5 секунд исполнения после готовности Python, отдельно до 60 секунд загрузки. На снимке не более 20 переменных; значение ограничено 256 символами, глубиной 4, первыми 12 элементами коллекции и бюджетом 80 узлов. stdout/stderr вместе ограничены 16 КиБ. По достижении лимита шагов/объёма Python останавливается исключением драйвера. Тайм-аут и отмена завершают Worker, сохраняя уже полученные шаги. Каждый новый запуск создаёт свежий Worker. Обработчики и таймеры очищаются после завершения и размонтирования.

Панель `debug-panel.tsx` показывает сохранённый код запуска с отдельной голубой подсветкой, шаги «Назад», «Следующий шаг», «Сначала» и таблицу переменных. Новые и изменённые видимые значения сравниваются в пределах одного кадра вызова, в том числе при рекурсии. Итоговый результат показывается на последнем шаге. Для ошибки/лимита сразу выбран последний доступный шаг. После редактирования трасса явно помечается устаревшей и продолжает показывать исходный снимок кода. Гипотеза ошибочной строки остаётся отдельной, фиолетовой, в основном редакторе.

Ограничения: коллекции и неизвестные объекты представлены сокращённо, изменения за пределами видимой части могут не различаться. Стандартная библиотека, динамически скомпилированный код, асинхронное выполнение и генераторы не являются отдельными поддерживаемыми сценариями просмотра. Содержимое внешних библиотек и сторонние потоки не трассируются. Worker не является защищённой песочницей, враждебный код может вмешаться в Python-механизм трассировки; внешний таймер всё равно завершает Worker.

Ручная проверка: откройте `/missions/missing-purchase`, выберите исходную строку 3 и нажмите «Отладка». На входе в тело цикла видны `i = 0`, `total = 0`, затем `i = 1`, `total = 100`. После второй итерации `total = 150`, последний шаг возвращает 150. Перед присваиванием `total = 0` эта переменная ещё отсутствует. Проверьте обратные шаги, «Сначала», сохранение выбранной строки и неизменный XP. Измените код: старая трасса помечается устаревшей. Повторная отладка использует новый черновик.

Проверки трассировки:

```powershell

npm.cmd run build
npm.cmd run test:browser -- tests/browser/trace.spec.ts
```

Первый набор выполняет фиксированные авторские примеры через локальный Python и проверяет Worker-контракт с управляемыми часами. Браузерный набор выполняет настоящий Pyodide в Chrome, проверяет снимки, рекурсию, исключения, лимиты, восстановление после тайм-аута, навигацию по шагам, отсутствие изменений localStorage и независимую отмену Run/Debug. Картинки проверки интерфейса сохраняются в игнорируемый `test-results/`.

### Обычный запуск и автоматическая проверка

Используется зафиксированный Pyodide 314.0.8. Runner из `src/lib/python/runner.ts` создаёт новый module Web Worker для каждого теста. Worker лениво загружает интерпретатор с самого сайта по пути `/pyodide/v314.0.8/`, получает исходник, имя функции, JSON-совместимые аргументы и requestId через сообщения. Постоянная Python-обёртка читает данные из отдельной JSON-переменной, компилирует исходник и вызывает функцию в новом namespace.

Worker собирается из TypeScript отдельной командой esbuild в `public/python.worker.mjs`. Эта же команда копирует пять файлов runtime из закреплённого npm-пакета в `public/pyodide/v314.0.8/`. `predev` и `prebuild` запускают подготовку автоматически. Это сохраняет настоящий module Worker при сборке Next.js через Turbopack и устраняет зависимость выполнения от CDN. Сгенерированные файлы исключены из Git. После изменения worker-кода во время разработки выполните `npm run build:worker` и обновите страницу.

Лимиты — 30 000 символов кода, 20 000 символов сериализованных аргументов, 16 КБ общего stdout/stderr, 30 000 символов JSON-результата, 30 уровней вложенности и 10 000 значений результата. Допускаются числа, строки, bool, None, списки и словари со строковыми ключами. Не поддерживаются NaN, Infinity, множества, tuple и целые числа вне точного диапазона JavaScript.

`SolutionVerifier` последовательно вызывает существующий Runner. Аргументы каждого теста клонируются. Новый Worker исключает перенос глобальных переменных, изменений встроенных функций и модулей между тестами. Параллельные проверки в одной миссии блокируются, при уходе проверка отменяется.

Загрузка одного Worker ограничена 60 секундами. На весь набор отведено суммарно 5 секунд исполнения после готовности интерпретаторов. Каждому следующему тесту передаётся оставшийся бюджет. Дополнительно действует общий лимит ожидания 120 секунд, включая загрузку. Лимит общего stdout/stderr набора — 16 КБ, размера набора — 20 тестов. Тайм-аут, отмена, ошибка загрузки или превышение лимита вывода останавливают набор. Оставшиеся тесты помечаются «Пропущен», поэтому частичный результат не принимается.

По завершении теста, ошибке, отмене или тайм-ауте Worker уничтожается через `terminate()`. requestId и проверка активного запуска защищают от устаревшего ответа. Следующая проверка работает со свежими Worker, включая после тайм-аута.

На каждом тесте создаётся свежий интерпретатор, статические файлы могут кешироваться браузером. Подготовленный runtime занимает примерно 13 МБ до сжатия. Web Worker изолирует выполнение от интерфейса, но полноценной защищённой песочницей не является. В MVP поддерживаются простые функции. `input()` отключён, интеграции с файлами пользователя, сетью и дополнительными Python-пакетами отсутствуют. Пользовательский Python исполняется на клиенте. Серверные маршруты исполнения отсутствуют.

Авторские тесты запускают фиксированные программы из репозитория локальным Python 3, проверяют все эталонные решения и провал хотя бы одного теста у каждой исходной программы. Бюджет шагов и тайм-аут процесса останавливают бесконечный цикл.

Тесты Runner проверяют раздельные таймеры, отмену, освобождение ресурсов, устаревшие ответы, лимиты вывода, ошибку Worker и повторный запуск. Браузерные тесты запускают настоящий Pyodide на production-сборке через установленный Google Chrome.

```powershell
npm.cmd run build
npm.cmd run test:browser
```

Playwright сам запускает production-сервер на порту 3100 и останавливает его после тестов. Требуется установленный Google Chrome. Проверяются все восемь эталонов и исходников через настоящий Runner и Pyodide, структурное сравнение, ошибки, изоляция, отправки, тайм-аут, отмена, уход со страницы, отказ загрузки и ширина 375/1440 px. Тестовый модуль проверяющего слоя собирается в памяти и доступен только через перехват запросов Playwright.

`tests/progress.test.ts` проверяет границы наград, отсутствие повторного XP, улучшения, подсказки, учитываемые попытки, отмену, сбои загрузки, уровни, достижения, восстановление, вкладки и повреждённое/недоступное хранилище. `tests/browser/progress.spec.ts` проверяет реальную выдачу и улучшение награды через Pyodide, профиль, прямой URL закрытой миссии, синхронизацию вкладок и очистку без потери черновиков. Для быстрой проверки этапа 4.1:

```powershell
npm.cmd run test:browser -- tests/browser/python-runner.spec.ts tests/browser/progress.spec.ts
```

Для `npm run test` нужен Python 3 в PATH. Можно указать путь через `$env:BUGHUNTER_PYTHON = 'C:\path\to\python.exe'`. Авторские проверки из `tests/` используются только при разработке. Приложению и Vercel Python не требуется.

## Стек и структура

Next.js App Router, React, TypeScript в строгом режиме, Tailwind CSS 4, ESLint и Lucide. Inter и JetBrains Mono поставляются локально через Fontsource с кириллицей. Рабочие версии зависимостей закреплены в `package.json` и `package-lock.json`.

```text
src/
  app/
    globals.css            дизайн-токены, компоненты и адаптивные стили
    layout.tsx             общий каркас и метаданные
    page.tsx               главная
    missions/page.tsx      каталог
    missions/[slug]/      страница миссии
    profile/              профиль
    leaderboard/          будущий рейтинг
    not-found.tsx          404
    icon.svg               иконка приложения
  components/
    ui.tsx                 логотип, карточки и общие элементы
    site-header.tsx        навигация с активным маршрутом
    site-footer.tsx        подвал
    code-preview.tsx       статичный пример кода
    mission-catalog.tsx    фильтрация каталога
    editor/               переиспользуемый CodeMirror-редактор
    missions/             общий интерфейс исследования миссии
    progress/             провайдер, награда, звёзды и гостевой профиль
  content/missions.ts      полные данные восьми миссий
  content/mission-tiers.ts общие категории
  lib/line-selection.ts   логика выбора исходной строки
  lib/mission-draft.ts    состояние ученика и localStorage
  lib/python/            протокол, Runner, лимиты и Python-обёртка
  lib/verification/      сравнение, проверка набора и React-хук
  lib/progress/          типы, правила, журнал, хранилище и состояние прогресса
  workers/python.worker.ts module Worker с Pyodide
  types/mission.ts         контракт миссии, тестов и трассировки
tests/                    метаданные, состояние и авторские Python-проверки
```

Страницы по умолчанию серверные. Клиентские компоненты отвечают за навигацию, фильтр и исследование миссии. `ReadyMission` содержит весь контракт подготовленного задания, а `LearnerMission` — учебный контент и метаданные браузерной проверки. `toLearnerMission` исключает эталонную реализацию. Правильная строка, дополнительные тесты и объяснение передаются в поле `verification` для клиентского grader. Эти данные доступны для инспектирования в браузере. Интерфейс раскрывает объяснение после успешной отправки. Клиентская проверка не даёт защищённого от подделки результата для соревнований.

`MissionWorkspace` управляет сценарием, `PythonEditor` отвечает за CodeMirror, `line-selection` за выбор строки, `mission-draft` за состояние. `SolutionVerifier` управляет набором, `grading` сравнивает результаты, а `PythonRunner` выполняет один независимый вызов функции.

Чтобы добавить задание, добавьте запись `ReadyMission` в `src/content/missions.ts` с уникальными id и slug и прогоните проверки. Каталог и страницы используют общий набор данных. Для бинарного поиска контракт этого задания задаёт возрастающий список без повторов, чтобы ожидаемый индекс был однозначным.

## Визуальная проверка

- Откройте главную на ширине 375 и 1440 px. Проверьте читаемость, переносы и отсутствие горизонтального скролла страницы.
- Перейдите по кнопке «Начать расследование» и проверьте все фильтры каталога. В полном списке должны быть восемь дел в трёх категориях.
- Откройте доступные карточки. У каждой свои история, условия, примеры и мини-теория. «Практик» и «Детектив» пока закрыты, в том числе при вводе URL вручную.
- Выберите строку кликом по коду, номеру или через список. Подсветка и сообщение должны соответствовать выбору.
- Перейдите в «Исправь код», измените код, откройте подсказку и обновите страницу. Черновик, гипотеза и подсказка должны восстановиться.
- Откройте другую миссию и вернитесь обратно. Данные миссий должны храниться независимо.
- Проверьте простой режим, восстановление исходного кода, подтверждение и отмену. Подсказки и выбранная исходная строка сохраняются при восстановлении кода.
- Нажмите «Запустить код». В первом деле исходный код проходит 1 из 3 публичных тестов. Число отправок остаётся нулевым, дополнительные тесты не отображаются.
- Вставьте `def sum_prices(prices):` и на следующей строке с четырьмя пробелами `print(prices); return sum(prices)`. Публичный запуск должен пройти 3 из 3 тестов и показать stdout для каждого.
- Выберите строку 2 и отправьте правильный код. Все 6 тестов проходят, но интерфейс предлагает пересмотреть строку. Правильный номер не раскрывается.
- Выберите строку 3 и отправьте снова. Должны появиться «Решение принято» и объяснение. Счётчик отправок равен 2. Проверьте его сохранение после обновления страницы.
- Измените принятый код. Результат должен быть помечен устаревшим. При обычном запуске отправки сохраняются, дополнительные тесты исчезают из панели.
- Попробуйте `return False`, `return None`, `return 1 / 0` и синтаксическую ошибку. Неверные типы и ошибки должны проваливать тесты.
- Вставьте бесконечный цикл `while True: pass` внутрь функции. Через 5 секунд после загрузки Python появится тайм-аут. После исправления следующий запуск должен работать.
- Проверьте отмену во время загрузки и выполнения и переход к каталогу при активном запуске. До выбора строки кнопка отправки отключена.
- Откройте профиль: XP, звёзды и достижения должны соответствовать принятым решениям и сохраняться после обновления. Рейтинг помечен «скоро».
- Пройдите миссию с двумя подсказками: 1 звезда и 50 XP. Нажмите «Пройти заново» и решите без подсказок с первой отправки: 3 звезды, общий XP увеличится только на 50. Повторная отправка даст 0 новых XP.
- Отмените отправку или заблокируйте загрузку Pyodide в DevTools: общий счётчик отправок увеличится, счётчик для награды останется прежним.
- Завершите три дела «Новичка», затем три дела «Практика». Проверьте открытие уровней, кнопку следующей миссии и карточки со звёздами.
- Откройте `/unknown` и `/missions/unknown`. Должна появиться 404 со ссылкой к миссиям.
- Пройдите интерфейс клавишами Tab и Enter. Проверьте видимую рамку фокуса и ссылку перехода к содержимому.
- Включите сокращение движения в системе. Плавная прокрутка и анимации переходов должны отключиться.

## Vercel

Каркас использует стандартную Next.js-сборку и готов для импорта репозитория в Vercel с preset Next.js. Команда сборки `npm run build`. Переменные окружения для этапа 1 не требуются. Публикация предусмотрена на этапе 5.

Python исполняется и проверяется в браузере внутри отдельных module Web Worker. При публикации дополнительно проверьте доступность `/python.worker.mjs` и файлов `/pyodide/v314.0.8/`. Они подготавливаются автоматически при `npm run build`.

Требования и порядок разработки находятся в `BugHunter_TZ.md` и `BugHunter_Codex_Prompts.md`.
