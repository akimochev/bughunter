# BugHunter — промпты для Codex (запускать последовательно)

## Как пользоваться

1. Открой папку проекта в VS Code и предоставь Codex файл `BugHunter_TZ.md` в корне проекта. Если он лежит отдельно, скопируй файл в корень.
2. В первый раз отправь **Промпт 0 — правила проекта** и **Промпт 1 — каркас**. Потом каждый следующий этап отправляй отдельным сообщением, только после проверки прошлого.
3. Каждый этап: изменения → `npm run lint`, `npm run build`, `npm run test` (когда появится) → запуск в браузере → исправление ошибок → commit.
4. Для V2 (авторизация, рейтинг) нужен Supabase-проект и переменные окружения. Без них MVP должен продолжать работать.

---

## Промпт 0. Постоянный контекст для Codex

```text
Ты — senior frontend/full-stack developer и product-minded engineer. Мы делаем BugHunter, русский интерактивный тренажёр по отладке Python для школьников 8–11 классов. Прочитай полностью BugHunter_TZ.md в корне репозитория и опирайся на него как на source of truth.

Основной сценарий: пользователь открывает детективную миссию, выбирает ошибочную строку в исходном коде, исправляет Python в редакторе, запускает публичные тесты, отправляет решение на полную проверку и получает объяснение, звёзды и XP.

Стек: Next.js App Router, TypeScript, Tailwind CSS, CodeMirror 6 (не Monaco-only, нужна мобильная версия), Pyodide в отдельном Web Worker, Vitest, Vercel. Без платных API. Позже (отдельный этап) Supabase Auth и лидерборд; пока проект работает локально без регистрации.

Требования к работе:
1. Сначала инспектируй текущий репозиторий, не удаляй существующие файлы без обоснования.
2. Составь короткий план только текущего этапа. Не реализуй другие этапы заранее.
3. Пиши рабочий, понятный и строго типизированный код. Не оставляй TODO-подмену основного сценария и не выдавай заглушки за работу.
4. Не используй моковые тесты там, где пользователь ожидает реальный запуск Python. Если на текущем этапе функционал ещё не реализован, явно обозначь «Скоро» или disabled.
5. Поддерживай русский язык интерфейса, удобство клавиатуры и мобильной версии. Не вставляй несуществующую статистику или фейковые отзывы.
6. Не запускай пользовательский Python на сервере. Не добавляй секреты в клиентский bundle.
7. Перед завершением этапа запускай доступные lint/typecheck/build/tests; исправляй обнаруженные проблемы.
8. В финале каждого этапа дай: (a) список изменённых файлов, (b) реализованные сценарии, (c) команды и их результаты, (d) что проверить мне вручную, (e) оставшиеся риски.
9. Когда для внешней интеграции потребуются аккаунты, credentials или ручные действия, не выдумывай их. Подготовь .env.example и точные инструкции.
10. Следуй BugHunter_TZ.md, но если замечаешь техническое противоречие — объясни и предложи минимальное исправление.

Сейчас не начинай кодирование без конкретного запроса этапа.
```

## Промпт 1. Каркас, страницы, дизайн

```text
Выполни ЭТАП 1 из BugHunter_TZ.md: создай работающую основу проекта (если репозиторий пуст — инициализируй Next.js App Router + TypeScript + Tailwind + ESLint + src/ + alias @/*, используя npm). Работай в текущей папке, на Windows/PowerShell.

Создай дизайн-систему: тёмный developer/detective, #0B1020 и #141D30, акцент #8B5CF6, Inter + моноширинный шрифт для кода, Lucide icons, аккуратные панели, состояния hover/focus/disabled. Продуктовый вид, не типичный шаблонный лендинг. Никакого чрезмерного неона.

Реализуй страницы /, /missions, /missions/[slug], /profile, /leaderboard. На главной — понятный hero, кто пользователь и чему научится, CTA к миссиям и 3 шага процесса. На /missions — 8 карточек и деление на 3 категории. На странице миссии — качественный layout (условие, редактор-плейсхолдер, результаты-плейсхолдер), но НЕ имитируй исполняемый код: до этапа runner показывай честную пометку о недоступности проверки. /profile — честный пустой прогресс, /leaderboard — «Рейтинг скоро», без фальшивых игроков.

Создай первичную типизированную модель Mission с полями из ТЗ, заглушки контента только для каркаса. Продумай адаптивность: 375px и 1440px, нет глобального горизонтального скролла, мобильная навигация понятна. Добавь полезные метаданные, favicon SVG, страницу 404.

Прогони lint и build. Дай команды запуска в PowerShell, список файлов и чеклист визуальной проверки. Не реализуй пока Pyodide, auth, leaderboard, XP.
```

## Промпт 2. Контент, выбор ошибочной строки, редактор

```text
Выполни ЭТАП 2 из BugHunter_TZ.md. Не трогай несвязанные страницы и не делай этап 3.

Реализуй все 8 миссий с реальными, методически корректными Python-функциями, одной намеренной ошибочной строкой в исходном коде, сюжетом, задачей, ограничениями входа, 2–3 публичными и 3–5 дополнительными тестами, эталонными решениями (только для авторских автоматических проверок), 3 последовательными подсказками, мини-теорией, объяснением бага.

Сделай редактор на CodeMirror 6 с синтаксисом Python, нумерацией строк, тёмной темой, корректной высотой и мобильным fallback. Добавь кликабельный gutter для выбора предполагаемой багованной строки и альтернативный доступный способ выбора строки с клавиатуры/на телефоне. Не показывай правильную строку до успеха. Выбор строки должен запоминаться отдельно от текста кода. Сделай сброс к исходному коду и сохранение черновика локально.

Выведи пример входа/выхода и мини-теорию, подсказки по очереди. «Запустить» и «Отправить» пока могут быть disabled с честным текстом «Проверка кода будет добавлена на следующем этапе» — никакого фальшивого успеха.

Добавь unit-тесты на корректность метаданных всех миссий: уникальный slug, корректное число тестов/подсказок, валидная строка бага, разные id тестов и т.д. Прогони lint, build, tests. В финале покажи одну полностью заполненную миссию и что проверить в браузере.
```

## Промпт 3. Настоящий Python runner — самый важный этап

```text
Выполни ЭТАП 3 из BugHunter_TZ.md. Главный приоритет — достоверный рабочий запуск и проверка Python, а не дополнительные анимации.

Интегрируй совместимую стабильную версию Pyodide в module Web Worker, с ленивой загрузкой при открытии миссии. Используй worker только на клиенте (никакого серверного выполнения пользовательского Python). Реализуй типизированный интерфейс runner: sourceCode + functionName + testCases -> per-test success/fail/error/timeout + stdout/stderr + duration.

Для V1 исполняй функции с JSON-совместимыми аргументами. «Запустить код» проверяет публичные тесты, не начисляет XP и не увеличивает submitAttempts. «Отправить решение» проверяет весь набор тестов и выбранную пользователем ошибочную строку. Проверяй возвращаемое значение без сравнения текста исходника с эталоном. Различай bool и int, массивы сравнивай с учётом порядка.

Нужны состояния загрузки runtime, run, submit, passed, failed, SyntaxError, Python exception, timeout, network/loading error. Ограничь вывод и размер кода; по таймауту (ориентир 3–5 сек на группу тестов после инициализации) заверши worker и восстанови возможность повторного запуска. Не допускай зависания главного потока. Изолируй состояние разных попыток и тестов. Не притворяйся, что Web Worker — полноценная безопасная песочница.

Напиши tests на 8 эталонных и 8 багованных программ: исправленный вариант проходит ВСЕ тесты, исходный — не менее одного теста проваливает. Добавь сценарии синтаксической ошибки, бесконечного цикла, пустого списка и неправильного типа результата; где headless browser нужен для Pyodide, добавь Playwright browser tests и опиши, какие реально запустились.

Прогони lint, build, tests. Если в браузере обнаружится проблема с загрузкой Pyodide/CDN/CSP/worker, исправь и повтори. В финале дай два примера ручной проверки: правильный и неправильный код.
```

## Промпт 4. Геймификация, подсказки, объяснения, Debug Mode

```text
Выполни ЭТАП 4 из BugHunter_TZ.md. Рабочий runner не менять без необходимости.

Добавь ProgressRepository и LocalProgressRepository с версионированным ключом localStorage, безопасной обработкой битого состояния и миграцией. Сохраняй черновик кода, выбранную строку, подсказки, submitAttempts, лучший результат миссии и достижения.

Реализуй точные правила открытия миссий, 1/2/3 звезды и XP 50/75/100 из ТЗ. XP за одну миссию нельзя накрутить повторными отправками: хранится лучший результат, начисляется только улучшение. Добавь 4 достижения из ТЗ и честный /profile.

После успешного Submit показывай объяснение конкретного бага, заработанные звёзды, XP и CTA следующего дела. Анимация успеха умеренная; respect prefers-reduced-motion. Три подсказки открываются последовательно; на итоговый рейтинг влияют подсказки и попытки. Чётко определяй, можно ли улучшать лучший результат при повторном прохождении.

Добавь панель пошаговой отладки для миссий 1 и 4. Это достоверная заранее подготовленная трасса ИСХОДНОГО багованного кода на одном конкретном входе, с выделением исполняемой строки и переменных, кнопками назад/вперёд. Не называй это универсальным trace для произвольного кода и не показывай её как результат редактирования пользователя.

Покрой тестами unlockRules, calculateStars, XP idempotency, achievements, corrupted storage. Прогони lint/build/tests и проверь перезагрузку страницы.
```

## Промпт 6. Опционально: регистрация и облачный прогресс

```text
Выполни ЭТАП 6 (V2) из BugHunter_TZ.md только после того, как MVP успешно работает. Добавь Supabase Auth и профиль с облачным прогрессом, не ухудшая гостевой сценарий.

Сначала предложи SQL migration для profiles и mission_progress с RLS и минимальными grants, .env.example, план входа (email OTP/magic link или password), затем реализуй после подготовки кода. Не создавай фиктивные ключи и не проси service-role key для браузера. Поддержи guest/local режим без env.

При первом входе предложи корректное слияние локального и серверного прогресса, без двойного XP. Публичное поле — только никнейм; никакие email и реальные сведения школьника в публичный API не выводить. Добавь логин, логаут, обработку ошибки входа, приватность профиля. Протестируй RLS: пользователь A не может читать и изменять приватный прогресс B.

Критически важно: сам факт синхронизации с клиентского Pyodide не делает результаты защищёнными от подделки. В README честно опиши это ограничение. Прогони lint/build/tests и дай список настроек, которые я должен сделать в Supabase dashboard.
```

## Промпт 7. Опционально: дружеский лидерборд

```text
Выполни ЭТАП 7 (V2) из BugHunter_TZ.md. Не подменяй рейтинг фальшивыми игроками. Реализуй публичный лидерборд только реальных зарегистрированных пользователей, которые согласились показывать никнейм в рейтинге.

Суммируй best_xp по уникальным миссиям, вычисляй ранги, отображай top N и мою позицию; продумай tie handling, пустое состояние, загрузку и отказ сети. Не возвращай email, токены, приватные поля. Защити БД RLS, grants и server-side/query layer; не разрешай клиенту записывать произвольный total XP. Добавь валидацию mission_id, best_stars, best_xp и ограничение частоты запросов.

Покажи в интерфейсе или правилах небольшое честное замечание: рейтинг дружеский, результаты базируются на клиентской проверке кода и не являются полностью защищёнными от накрутки. Не выдавай это за защищённый конкурс. Для настоящей античит-системы нужен отдельный доверенный evaluator и это вне scope.

Прогони lint/build/tests, проверь двух пользователей и предложи ручной smoke test на опубликованном сайте. Гостю рейтинг доступен к просмотру, но не к участию.
```

## Полезные команды для Windows PowerShell

```powershell
# Если папка уже создана и в ней есть package.json:
npm install
npm run dev

# В отдельных проверках:
npm run lint
npm run build
npm run test

# Git после проверенного этапа:
git status
git add .
git commit -m "feat: complete BugHunter stage 1"
```

Если проект ещё не создан, Этап 1 сам создаёт его. **Не выполняй `npx create-next-app` поверх готового проекта без проверки содержимого папки.**

## Что проверять самостоятельно после каждого этапа

- **1:** красивые страницы и адаптивность, переходы работают.
- **2:** корректный редактор и выбор строки на телефоне/ПК, контент 8 миссий.
- **3:** нажатие Run действительно исполняет Python; неверный код падает; правильный проходит; бесконечный цикл не вешает сайт.
- **4:** прогресс сохраняется после F5, XP не дублируются, trace честно подписан.
- **5:** опубликованная ссылка работает с телефона без авторизации.
- **6:** вход/выход и облачный прогресс, гостевой режим не сломан.
- **7:** рейтинг с настоящими пользователями, без персональных данных и фальшивых записей.
