# BugHunter — техническое задание

**Версия:** 1.0 (план для тестового задания AI Product Builder / Vibe-coder)  
**Дата:** 15 ноября 2026  
**Язык продукта:** русский  
**Целевая аудитория:** школьники 8–11 классов, от знакомства с основами Python до простых алгоритмов.

## 1. Продукт и цель

BugHunter — браузерный образовательный тренажёр по отладке Python в детективной стилистике. Вместо решения задач с нуля пользователь получает «сломанный» код, находит ошибочную строку, исправляет код в редакторе, запускает тесты и узнаёт причину ошибки. Продукт должен быть понятен без инструкции, удобен на компьютере и телефоне и открываться по публичной ссылке.

**Обещание пользователю:** «Код сломан. Найди ошибку. Исправь. Прокачай Python».

**Критерий успеха тестового:** незнакомый с проектом человек за 30–60 секунд понимает назначение, открывает миссию, исправляет хотя бы одну ошибку, получает правдивую обратную связь. Проверяющий может повторить путь на телефоне.

## 2. Объём версий

### V1 — обязательный MVP, без внешнего backend и API
- Полноценная главная, каталог миссий, экран задачи, профиль прогресса.
- 8 тщательно проверенных миссий с проверкой Python-кода.
- На каждой миссии: сюжет, цель, начальный код с багом, выбор строки, редактор, «Запустить код», «Отправить решение», тесты, подсказки 1–3, объяснение после успеха, мини-теория.
- Исполнение Python в Pyodide внутри Web Worker; остановка зависшего исполнения, ограничение времени и размера вывода.
- 2 миссии с пошаговой визуализацией **исходного сломанного кода** по заранее подготовленному достоверному trace; это не универсальный debugger произвольного Python.
- XP, звёзды, 4 достижения, открытие уровней, сохранение состояния в localStorage, конфетти/анимация успеха с учётом reduced-motion.
- Адаптивность для ~360px+, рабочий мобильный редактор.
- Публичная ссылка на Vercel и README с командами разработки.

### V2 — отдельный этап, не блокирует сдачу V1
- Необязательная авторизация Supabase Auth; гость может пользоваться всеми миссиями.
- Никнейм/аватар-иконка без требования настоящих персональных данных.
- Перенос локального прогресса в облако после первого входа, синхронизация между устройствами.
- Публичный лидерборд только по никнейму и очкам, с равенством очков, местом пользователя, пустым состоянием.
- RLS и серверные операции по принципу минимальных прав.

**Принципиальное ограничение V2:** результаты, подтверждённые только исполнением в браузере, можно подделать. Такой лидерборд является дружеским/демонстрационным и не годится для призов, соревнований и заявлений о защищённом ранжировании. Для честного рейтинга нужен доверенный серверный grader или иной способ серверной валидации; не запускать произвольный ученический Python в Vercel API route.

## 3. Дизайн и язык

- Тёмный developer / detective стиль, а не тяжёлый киберпанк: фон `#0B1020`, карточки `#141D30`, цвет интерфейса `#8B5CF6`, удачный ответ `#22C55E`, подсказка `#F59E0B`, ошибка `#F87171`.
- Inter или аналог для интерфейса, JetBrains Mono или аналог для кода (через законные публичные источники); не загружать сторонние приватные ассеты.
- Тон: дружелюбный, чуть игровой, без снисходительности. Текст полностью на русском; технические термины Python остаются как есть.
- Статусы: «Дело открыто», «Ошибка найдена», «Тесты пройдены», «Дело закрыто».
- Простые анимации, микровзаимодействия, skeleton/loading для первого старта Pyodide. Уважать `prefers-reduced-motion`.
- Контраст, видимые focus-стили, читаемость на телефоне. Не использовать цвет как единственный сигнал ошибки.

## 4. Навигация и страницы

### `/` — главная
- Логотип BugHunter, слоган и подзаголовок с указанием класса, языка программирования и результата обучения.
- Hero с дизайнерской, но реальной мини-сценой проверки кода; CTA «Начать расследование».
- Блок «Как это работает»: найти строку → исправить → запустить → получить объяснение.
- Превью миссий, преимущества (практика, мгновенная обратная связь, бесплатно).
- Шапка: миссии, рейтинг (V2 / пометка «скоро» в V1), профиль. Без фейковых отзывов и фальшивых цифр.

### `/missions` — карта дел
- Карточки 8 миссий: номер, название, тема, уровень, время приблизительное (если указывать — только ориентир), состояние, звёзды.
- 3 группы: «Новичок», «Практик», «Детектив».
- Разблокировка: 1–3 доступны; 4–6 доступны после двух завершённых простых миссий; 7 после пяти любых завершённых миссий; 8 после семи завершённых. Понятное объяснение, почему заблокировано.
- Фильтр уровня и панель прогресса (не обязательны к первому экрану, но в V1 желательны).

### `/missions/[slug]` — игровой экран
- Верх: хлебные крошки, название дела, уровень, очки, статус.
- Левая колонка desktop: история, формальные требования функции, примеры входа/выхода, мини-теория и 3 подсказки.
- Правая колонка desktop: интерактивный CodeMirror 6 с подсветкой Python и нумерацией строк; выбор ошибочной строки кликом по номеру / тапом / клавиатурным доступным альтернативным контролом.
- На телефоне: компактная шапка, условие (сворачиваемое), редактор шириной экрана с горизонтальным скроллом внутри и крупными доступными кнопками, тесты ниже. Никакого горизонтального скролла всей страницы.
- Этап A «Найди строку»: пользователь выделяет предполагаемую проблемную строку; она запоминается независимо от изменения кода. До подтверждения строки кнопка «Отправить» недоступна либо показывает ясную инструкцию.
- Этап B «Исправь»: доступный редактор, кнопка «Сбросить код», при уходе сохраняется черновик.
- «Запустить код»: публичные 2–3 теста, результаты по отдельности, stdout/stderr и дружелюбные сообщения об ошибках. Можно запускать многократно; XP не меняется.
- «Отправить решение»: публичные + дополнительные тесты; проверка выбранной строки и всех тестов; только отправки увеличивают счётчик попыток.
- Три подсказки раскрываются последовательно, не открывают сразу точный фикс (третья очень близко подводит).
- После успеха: объяснение сути бага, пример прохождения тестов, звёзды, XP, приятная анимация, CTA к следующей миссии.
- «Пошаговая отладка» для 2 выбранных дел: панель с заранее рассчитанной трассировкой исходного багованного кода и конкретного примера входа. Явная подпись, что это трасса исходной программы; после пользовательских правок trace не выдается за трассу изменённого кода.

### `/profile` — профиль прогресса (V1 локальный)
- Никнейм гостя «Детектив» или «Гость»; XP, решено из 8, лучшие звёзды, достижения, список пройденных миссий. Возможность очистить локальный прогресс с подтверждением.
- После V2 показывать авторизованный профиль, но сохранять функциональность гостя.

### `/leaderboard` и `/auth` (V2)
- Лидерборд по публичным никнеймам, без email/имён/возраста. Если V2 ещё не сделана, показывать честную заглушку «Рейтинг появится позже», без фальшивых игроков.
- `/auth`: вход/регистрация, аккуратные ошибки, восстановление доступа при поддерживаемом способе, кнопка продолжения без регистрации.

## 5. Учебный контент: 8 миссий

Каждая миссия обязана иметь реалистичный кейс, одну явно обозначенную исходную ошибочную строку, корректную эталонную функцию, 2–3 публичных и 3–5 дополнительных тестов, граничные случаи, 3 подсказки, мини-теорию и краткое объяснение. Сложность растёт постепенно.

| № | Дело | Функция / баг | Знание | Категория |
|---|---|---|---|---|
| 1 | Пропавшая покупка | `sum_prices(prices)`: `range(len(prices) - 1)` пропускает последний элемент | `range`, циклы | Новичок |
| 2 | Пароль чётности | `is_even(n)`: неверное условие остатка | условие, `%` | Новичок |
| 3 | Преждевременный ответ | `count_occurrences(nums, target)`: `return` внутри цикла | `return`, цикл | Новичок |
| 4 | Потерянный рекорд | `find_max(nums)`: максимум начинается с `0`, ошибка на полностью отрицательных списках; вход всегда непустой | граничные случаи | Практик |
| 5 | Бесконечный обратный отсчёт | `countdown(n)`: в `while` счётчик движется не в ту сторону; `n>=0` | `while`, завершение | Практик |
| 6 | Сломанный фильтр | `filter_positive(nums)`: условие ошибочно включает `0` или исключает положительное значение | списки и фильтрация | Практик |
| 7 | Бинарный сбой | `binary_search(sorted_nums, target)`: неверная правая граница / особый случай отсутствия | бинарный поиск | Детектив |
| 8 | Два указателя | `has_pair(sorted_nums, target)`: указатель движется в неверном направлении при малой сумме | два указателя | Детектив |

**Правило разработки контента:** перед включением каждой миссии реально запустить эталонное решение и убедиться, что (1) багованное решение падает хотя бы на одном тесте, (2) исправленный код проходит все тесты, (3) подсказки и правильная строка соответствуют реальному багу, (4) зависающие решения корректно останавливаются.

## 6. Исполнение и проверка кода

### Контракт задачи
Все задания V1 — чистые Python-функции без интерактивного `input()`, файлов, сети и внешних библиотек. Примеры и тесты представлены JSON-совместимыми аргументами/ожидаемыми значениями (числа, строки, списки, bool, null и сочетания), чтобы браузерный runner был прост и предсказуем.

Пример схемы TypeScript (допустимо улучшить типы):

```ts
type TestCase = { id: string; args: unknown[]; expected: unknown; isPublic: boolean };
type TraceStep = { line: number; variables: Record<string, unknown>; note: string };
type Mission = {
  id: number; slug: string; title: string; tier: 'beginner'|'intermediate'|'advanced';
  story: string; goal: string; topic: string; functionName: string;
  starterCode: string; buggyLine: number; referenceSolution: string;
  publicTests: TestCase[]; hiddenTests: TestCase[];
  hints: [string,string,string]; theory: string; explanation: string;
  trace?: { inputLabel: string; steps: TraceStep[] };
};
```

`referenceSolution` может использоваться для авторских тестов и не должен показываться до успешного решения. В браузерном MVP он не секретен: весь JS и контент доступны инспектированию. Дополнительные тесты также не защищены от просмотра — обозначать их «дополнительными», не обещать криптографической тайны.

### Runner
- Pyodide работает **только на клиенте** внутри отдельного module Web Worker, никогда в server action/API route/Node-процессе на Vercel.
- Отдельный слой runner принимает `sourceCode`, `functionName`, `testCases`, возвращает структурированный результат `passed/failed/error/timeout`, stdout/stderr и детализацию.
- Перед каждым запуском пользовательская функция и тесты исполняются в свежем Python namespace/изолированном контексте теста, чтобы состояние не протекало между запусками. Если точная изоляция затруднена, создавать новый worker на проверку или доказуемо сбрасывать состояние.
- Установить разумный тайм-аут на **весь запуск** (например, 3–5 сек после загрузки runtime), ограничить вывод/размер кода и число тестов; при превышении останавливать worker через `terminate()` и при следующем запуске создавать заново. Это не универсальная защита от произвольного кода.
- Отдельные статусы: загрузка Pyodide, выполняется, прошло, не прошло, ошибка Python, тайм-аут, проблема загрузки runtime. Пользователь понимает, что делать дальше.
- Сравнение результатов по нормализованным JSON-значениям: `bool` не должен смешиваться с `int`; массивы учитывают порядок; сложные типы вне MVP.
- Не выполняем произвольный код на сервере; не сохраняем пользовательский Python на публичный сервер без явной необходимости.
- Код, дописанный учеником, не должен иметь доступ к Supabase service-role keys, токенам других пользователей, серверным секретам.

### Правила проверки
- «Запустить код» исполняет публичные тесты, не повышает число попыток, не даёт XP.
- «Отправить решение» исполняет все тесты; для победы нужны верная **исходная** багованная строка и успешные тесты.
- Ошибочная строка выбирается на стартовом коде; можно не принимать большие переписывания как «ошибка найдена» без соответствующей метки. При каждой отправке проверять актуальный код, не текстовый exact-match с эталоном.
- Ошибки показывать без раскрытия решения. Детализация дополнительных тестов после отправки: статус и полезное сообщение, но можно не раскрывать полный набор кейсов.
- Ошибки синтаксиса (`SyntaxError`), вызова (`TypeError`), неверное значение и бесконечный цикл — отдельные понятные состояния.

## 7. Геймификация и хранение данных

### Открытие миссий
- 1–3 доступны сразу.
- 4–6 после 2 завершённых дел уровня «Новичок».
- 7 после 5 завершённых дел всего.
- 8 после 7 завершённых дел всего.

### Звёзды и XP
- 3 звезды: без подсказок, не более 2 отправок.
- 2 звезды: не более одной подсказки и не более 4 отправок, если не выполнены условия 3 звёзд.
- 1 звезда: успешное решение в остальных случаях.
- XP за миссию: 3 звезды = 100, 2 = 75, 1 = 50.
- На каждую миссию хранится **лучший** результат. Повторная победа не начисляет очки повторно; если лучший результат улучшился — добавляется только разница.
- Попытки и подсказки учитываются в рамках текущего прохождения; «Начать заново» не должно позволять бесплатно сбросить штрафы в рамках одной попытки прохождения. Для улучшения результата можно начать отдельное прохождение, но правила должны быть явными.

### Достижения
- «Первое дело» — завершить 1 миссию.
- «Без единой подсказки» — завершить миссию на 3 звезды.
- «Мастер циклов» — завершить миссии 1, 3 и 5.
- «Охотник за багами» — завершить все 8 дел.

### localStorage
- Версионированная схема `bughunter_progress_v1`, миграция/защита от битого JSON, сохранение попыток, подсказок, черновика и завершённых миссий.
- Разделить `ProgressRepository` (интерфейс) и `LocalProgressRepository` (реализация), чтобы подключить Supabase в V2 без переписывания компонентов.
- При сбросе показывать подтверждение, не затрагивать чужие данные.

## 8. Авторизация и лидерборд (V2)

### Auth
- Supabase Auth (например, email + одноразовая ссылка или пароль; выбрать один понятный поток); анонимное прохождение не блокировать.
- Таблица `profiles(user_id, nickname, created_at)`; nicknames с длиной/допустимыми символами, уникальность по нормализованному имени; не собирать класс, дату рождения, пол, реальные ФИО.
- Таблица `mission_progress(user_id, mission_id, best_stars, best_xp, completed_at)` с уникальным `(user_id, mission_id)`; дополнительные приватные черновики — опционально.
- Клиентские адаптеры `SupabaseProgressRepository`, `AuthProvider`; слияние по `max(best_stars)` и `max(best_xp)` при первом входе (не суммировать повторные победы).
- RLS: пользователь читает/изменяет только свою запись прогресса; минимальные GRANT; публичная выдача лидерборда возвращает только nickname/score/rank, не email/идентификаторы сессий.
- Отсутствие env-переменных Supabase не ломает V1: гостевой режим продолжает работать.

### Лидерборд
- Рейтинг по **сумме лучших XP для каждой миссии**; один участник один ряд. Для равных очков обозначить равные места или задать стабильное публичное правило ничьей.
- Не показывать реальные персональные данные школьников и не вводить публичный чат.
- Все подсчёты очков на сервере/в БД по завершённым миссиям, не принимать произвольное число total XP из клиента. Однако без доверенного оценивания кода завершение миссии всё равно можно подделать; отметить ограничения рейтинга.
- Против случайного спама: ограничения частоты записи, валидация mission_id, звезд и верхней границы XP, RLS, индексы, запрет массовой записи чужим пользователям.
- Для полноценной защищённости рейтинга нужен отдельный серверный валидатор, который не входит в бесплатный учебный MVP.

## 9. Стек

- Next.js (App Router), React, TypeScript, Tailwind CSS, shadcn/ui по необходимости.
- CodeMirror 6 + Python language support, темы, нумерация строк и маркер проблемной строки. **Не Monaco** как единственный редактор: официально не заявлена поддержка мобильных браузеров.
- Pyodide в Web Worker, браузерное исполнение.
- Lucide icons, CSS animations / Framer Motion или Motion при необходимости, лёгкое конфетти.
- Vitest для проверки правил миссий/прогресса, Playwright для ключевого E2E в Chrome (если возможно в среде).
- Supabase для V2; Vercel для деплоя. Никаких платных AI API.
- Зафиксировать рабочие версии зависимостей после проверки совместимости; использовать актуальные стабильные релизы вместо слепого копирования номеров.

Это ориентир, не жёсткое ограничение. Не создавать чрезмерно сложную систему папок ради архитектуры.

## 11. Критерии приёмки

1. Старт в Windows PowerShell: `npm install`, `npm run dev`, сайт виден по `http://localhost:3000`.
2. `npm run lint`, `npm run build`, `npm run test` завершаются успешно (если тестовая команда добавлена).
3. Пользователь без регистрации открывает миссию, выбирает правильную строку, исправляет баг, проходит тесты.
4. Неправильный код не получает победу; видны проваленные тесты и ошибки; тайм-аут не блокирует страницу.
5. 8 задач пройдены эталонными решениями и не пройдены исходным багованным кодом хотя бы на одном тесте.
6. «Запустить код» и «Отправить решение» работают по-разному и не смешивают состояние.
7. XP начисляются без дублирования, разблокировка дел работает, прогресс переживает перезагрузку.
8. У каждой миссии есть 3 подсказки и корректное объяснение, как возникла ошибка.
9. На 2 миссиях достоверно показывается трасса **исходного** кода.
10. Интерфейс удобен на 375px и 1440px; редактор можно использовать на телефоне; нет горизонтального скролла всей страницы.
11. Нет фальшивой функциональности: кнопки работают, если функция не реализована — она честно помечена.
12. Деплой на Vercel открывается публично; проверить одну миссию в production, особенно загрузку Pyodide/worker.
13. README содержит назначение, стек, запуск, этапы, ограничения браузерного раннера и (если есть) ограничения лидерборда.

## 12. Что не делаем в V1

AI-чат, мультиплеер, рейтинговые призы, школьные кабинеты преподавателя, постоянный backend, любые платные AI API, исполнение Python на Vercel Functions, загрузку произвольных файлов, персонализированную аналитику несовершеннолетних, сбор настоящих имён.
